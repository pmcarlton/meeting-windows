# Meeting windows

Open `index.html` directly in a modern desktop browser, or serve the repository directory with any static web server. The interface is designed for a large display with a mouse and keyboard; it keeps a desktop layout at narrow widths. No build, account, calendar connection, or runtime network requests are needed. Preferences and ranges are saved in the browser's local storage.

1. Choose your timezone and the recipient's timezone. Search about 34,000 cities, IANA identifiers, long timezone names, common abbreviations, or UTC offsets (for example `UTC+05:30`). The default map mode, Viewport focus, uses a rotated cylindrical latitude lens. Its horizontal center line has equal east/west and north/south local scale; compression increases toward the top and bottom. North/south panning rotates the sphere so the focus follows the viewport, including both poles. Reset opens an equator-centered overview. Scroll horizontally with the arrows, trackpad, wheel, or touchscreen; click a region or city. “Me” and “Them” choose which timezone the map changes.
2. Drag a rectangle across the week grid to add the same clock-time window on each included day. Dragging from Monday 9am to Tuesday 9am selects only the 9–9:30am cell on each day. Drag from a selected cell to erase a rectangle, splitting existing ranges where needed. Use the arrows or date control for another week. Use Exact ranges for an overnight interval. Keyboard users can Tab to a cell and press Space or Enter.
3. Edit Exact ranges for minute precision, dates beyond the displayed week, or overnight intervals. Add as many non-contiguous ranges as needed.
4. Use **Copy their times** for the recipient's timezone, or **Copy my times** to share the same availability in your local timezone. The latter starts with “my” instead of “your”. Both use the current sentence-piece/list and 12/24-hour settings. The visible preview remains in the recipient's timezone.

General controls, text, and map labels use neutral slate colors. Orange identifies My timezone and green identifies Their timezone, including cards, axes, away shading, and selected map regions. Base map UTC offsets use muted blue/violet shades; hover uses violet. Person labels remain visible alongside color cues.

The calendar shades your away hours in pale orange and theirs in pale green; overlapping away hours use a blended color. Selected availability is blue and takes precedence over all away-hour backgrounds. Shading follows each person's local clock on each date, including daylight-saving changes and fractional-hour offsets. It does not prevent selecting a time. A partial half-hour slot can contain more than one color. Hover text shows both people's local dates and times; repeated source hours show both occurrences and their UTC offsets.

Open **Settings** at the bottom of the page to change each person's daily away-hour range, turn either shading layer off, set your default timezone, and manage the cities shown on the map. An overnight range such as 18:00–08:00 is supported. Equal start and end times disable that layer. A new default timezone applies immediately and on reopening the app. Ordinary changes to My timezone are temporary; reopening restores the configured default. Favorites are the map's city pins: the original 22 map cities are included initially. Add cities by searching in Settings. The empty dropdowns show saved map cities, with an × to remove each city. Choosing a city in a timezone dropdown changes the timezone without adding a favorite. Removal does not change either selected timezone. Previously saved favorites are retained when migrating from the earlier additive favorites feature. These preferences are saved locally alongside selections.

Pinch the map with two fingers or a trackpad to zoom, or use + and −. Drag to pan. In Viewport focus, Reset returns to 100% with the equator centered; in the other modes it centers the selected person’s timezone. The map repeats beyond both edges with about a quarter viewport of overlap. Repeated regions and city pins remain clickable. SVG references reuse the geometry and keep the added overlap lightweight. Normal zoom is limited to 100–400%; Align Cities and Frame Cities can fit below 100% when needed. The small D3 geometry libraries are bundled locally; no external map or geocoding service is used. Trackpads use Ctrl+wheel in Chromium or gesture events in WebKit; touchscreens use pointer gestures directly.

In Settings, Map projection lets you compare Viewport focus, the earlier latitude-expansion-on-zoom mode, or the original equal-area map. The city-based overview has been removed; a saved city-based preference migrates to Viewport focus. Existing saved preferences for the other modes are retained. For Viewport focus, drag in any direction, use a trackpad or wheel, or focus the map and use its arrow keys; Home centers the equator without changing zoom. Both poles can be centered at any zoom level. Zoom buttons preserve the viewport center, and pinch/Ctrl+wheel use the pointer as an anchor. The center line is a rotated great circle, so geographic meridians and parallels curve away from the focus. This mode recalculates geometry during panning as well as zooming.

**Align Cities** reorients Viewport focus so the shorter great-circle segment between My city and Their city lies horizontally through the viewport center. It centers the spherical midpoint and fits both endpoints with padding. Of the two horizontal orientations, it chooses the one with the North Pole toward the top, so either city may appear on the left. Swapping My and Their cities preserves the orientation. If the connecting great circle passes through a pole, that pole lies on the centerline and cannot be placed above it. The operation switches to Viewport focus if needed. For a narrow map viewport it can fit below 100% zoom; Reset restores the normal 100% equator-centered, north-up overview. Zoom preserves the rotation; panning moves away from the aligned view. Click Align Cities again to recenter it. This is a one-click reorientation, not a persistent lock.

**Frame Cities** centers the midpoint of the shorter longitude interval and the average latitude. It uses a north-up cylindrical latitude lens: meridians stay vertical and latitude order is preserved, with the greatest latitude expansion at the center. Zoom fits both cities in both dimensions with padding. Labels point inward, are kept inside the viewport, and appear even for cities outside the favorites list. A large latitude difference can limit zoom before the cities reach the left and right edges. Coincident cities are supported; exactly opposite longitudes use a consistent choice of the two possible midpoints. Zooming and panning keep this north-up view; Reset or Align Cities returns to the regular viewport-focus projection. Resizing refits an untouched framed view.

Both buttons require two actual cities selected from search, favorites, or map pins. A timezone name or region does not supply city coordinates. For Align Cities, identical locations and points within about 6 meters of being exactly antipodal are disabled, since there is no stable unique shorter arc; the button tooltip explains why. Saved city selections retain their coordinates on reopening, including the configured default city. Older preferences that lost coordinates are recovered when a distinct city name and its timezone identify one location. Timezone display names alone and ambiguous city names are not guessed; select an actual city for those cases. Selected cities are labeled in all map modes, including cities outside the favorites list.

The bottom-left map caption shows only the currently hovered timezone. It clears when the pointer leaves the map, the hover ends, or the view changes.

ME and THEM labels sit in a separate strip beneath the map, aligned with the visible location markers. They stay clear of city names and follow horizontal panning and zoom. Labels for locations outside the current view are hidden; nearby labels separate so both remain readable.

Changing your timezone preserves the entered local dates and clock times. Changing the recipient's timezone preserves your availability. Overlapping or adjacent intervals merge for output. The text names the timezone once, shortens months and clock times, and ends with the year in brackets. Cross-midnight intervals include both dates. Timezone names appear at the first clause and whenever the timezone changes. A continuous interval whose endpoints use different offsets names the ending timezone immediately after “to”. Clock times stay free of repeated abbreviations. If the same long timezone name describes different offsets, its UTC offset is included to distinguish them. Dates spanning different years include those years beside the dates. Endpoints in skipped hours are rejected; endpoints in repeated hours require an explicit first/second occurrence choice. Times mean the complete available window, not permissible meeting start times.

The app uses the browser's built-in IANA timezone rules through `Intl.DateTimeFormat`. Keep your browser and operating system current for timezone law changes. Dates from 1900 through 2100 are supported; the UI is intended for present/future meeting scheduling.

The calendar always opens to the current week in your selected timezone. It does not restore a previously viewed week.

Source: `time.js` contains conversion, formatting, and away-hour calculations; `app.js` contains controls and city search; `settings.js` manages preferences and favorites; `map.js` draws the map and handles gestures; `projection.js` contains the earlier projection blend and inverse mapping; `focus-projection.js` and `focus-map.js` implement the viewport focus mode; `style.css` contains presentation. Geographic data licenses and attribution are in `DATA.md`.

Run regression checks with `node tests.cjs`, `node projection-tests.cjs`, `node focus-tests.cjs`, `node availability-tests.cjs`, and `node grid-tests.cjs`. Add `?profile=1` to the URL to reveal the optional zoom comparison; it keeps the map onscreen and reports update times and animation frame intervals for the original and the adaptive and viewport-focus modes. These timings include JavaScript and synchronous browser work, not an isolated GPU measurement.

## GitHub Pages updates

The live app is https://pmcarlton.github.io/meeting-windows/. GitHub Pages publishes `main` from the repository root. No build step is needed. Keep the HTML, JavaScript, CSS, bundled data, and vendor files together.

Make changes in this repository, run the regression checks above, then commit and push to `main`. GitHub Pages normally updates within a few minutes. Use a hard refresh if the browser still shows an older copy. `LICENSE` covers the application; `DATA.md` and the vendor license files document bundled third-party material.

The timezone controls and scheduling workspace come first; the map follows, with Settings at the bottom. The calendar heading names the input timezone. The global Time format control applies to both clock axes, hover descriptions, generated text, and its conversion preview.

The right-hand Their axis follows the highlighted day column as the pointer or keyboard focus moves between days. Its heading identifies the source column. This keeps it accurate when offsets change during the week; it is not a fixed offset shared by every column. A small dated tick marks the recipient's midnight, including fractional-hour positions. Skipped source clock times have no corresponding label; repeated source hours can have two recipient clock labels.

Valid overlapping or adjacent selected windows merge into one exact range, including windows that join across midnight. Merging uses actual instants and preserves explicit first/second choices during repeated hours. Invalid or unresolved drafts stay separate for correction. New manually added drafts stay editable until changed. Exact controls keep focus during edits and merges. Blue cell shading covers only the selected fraction of each half-hour.

Undo restores the previous availability after a selection, erase, exact-field edit, added/deleted range, or Clear all. Up to 40 availability changes are kept in memory for this session. Click Undo, or press Cmd+Z / Ctrl+Z outside text fields; native text undo remains available inside fields. Reloading or changing the input timezone clears this history. Recipient timezone and map changes are outside availability history.

Clock changes in either timezone are marked on the grid: orange for My clock, green for Their clock. A badge on the affected date names the old and new abbreviations (or the shift amount when the names are long), a colored boundary distinguishes that date column, and a dashed tick marks the actual change time. Hover a badge for full timezone names, UTC offsets, the amount of the change, and its date/time for each person. Recipient changes are placed in the corresponding My date column, which may differ from their local date. These markers include permanent offset changes and fractional-hour DST shifts.

The grid-commit regression check starts from no availability, adds multiple independent selections, verifies generated text, then checks merging, rectangular selection, erasing, and skipped hours.
