# Meeting windows

Open `index.html` directly in a modern browser, or serve the repository directory with any static web server. No build, account, calendar connection, or runtime network requests are needed. Preferences and ranges are saved in the browser's local storage.

1. Choose your timezone and the recipient's timezone. Search about 34,000 cities, IANA identifiers, long timezone names, common abbreviations, or UTC offsets (for example `UTC+05:30`). The default map mode, Viewport focus, uses a rotated cylindrical latitude lens. Its horizontal center line has equal east/west and north/south local scale; compression increases toward the top and bottom. North/south panning rotates the sphere so the focus follows the viewport, including both poles. Reset opens an equator-centered overview. Scroll horizontally with the arrows, trackpad, wheel, or touchscreen; click a region or city. “Me” and “Them” choose which timezone the map changes.
2. Drag a rectangle across the week grid to add the same clock-time window on each included day. Dragging from Monday 9am to Tuesday 9am selects only the 9–9:30am cell on each day. Drag from a selected cell to erase a rectangle, splitting existing ranges where needed. Use the arrows or date control for another week. Use Exact ranges for an overnight interval. On touchscreens, tap half-hour cells; use Exact ranges for longer intervals. Keyboard users can Tab to a cell and press Space or Enter.
3. Edit Exact ranges for minute precision, dates beyond the displayed week, or overnight intervals. Add as many non-contiguous ranges as needed.
4. Copy the generated sentence piece or list in the recipient's timezone.

The calendar shades your away hours in pale orange and theirs in pale green; overlapping away hours use a blended color. Selected availability is blue and takes precedence over all away-hour backgrounds. Shading follows each person's local clock on each date, including daylight-saving changes and fractional-hour offsets. It does not prevent selecting a time. A partial half-hour slot can contain more than one color. Hover text shows both people's local dates and times; repeated source hours show both occurrences and their UTC offsets.

Open **Settings** to change each person's daily away-hour range, turn either shading layer off, set your default timezone, and manage the cities shown on the map. An overnight range such as 18:00–08:00 is supported. Equal start and end times disable that layer. A new default timezone applies immediately and on reopening the app. Ordinary changes to My timezone are temporary; reopening restores the configured default. Favorites are the map's city pins: the original 22 map cities are included initially. Add cities by searching in Settings. The empty dropdowns show saved map cities, with an × to remove each city. Choosing a city in a timezone dropdown changes the timezone without adding a favorite. Removal does not change either selected timezone. Previously saved favorites are retained when migrating from the earlier additive favorites feature. These preferences are saved locally alongside selections.

Pinch the map with two fingers or a trackpad to zoom, or use + and −. Drag to pan. In Viewport focus, Reset returns to 100% with the equator centered; in the other modes it centers the selected person’s timezone. The map repeats beyond both edges with about a quarter viewport of overlap. Repeated regions and city pins remain clickable. SVG references reuse the geometry and keep the added overlap lightweight. Zoom is limited to 100–400%. The small D3 geometry libraries are bundled locally; no external map or geocoding service is used. Trackpads use Ctrl+wheel in Chromium or gesture events in WebKit; touchscreens use pointer gestures directly.

In Settings, Map projection lets you compare Viewport focus, the earlier latitude-expansion-on-zoom mode, or the original equal-area map. The city-based overview has been removed; a saved city-based preference migrates to Viewport focus. Existing saved preferences for the other modes are retained. For Viewport focus, drag in any direction, use a trackpad or wheel, or focus the map and use its arrow keys; Home centers the equator without changing zoom. Both poles can be centered at any zoom level. Zoom buttons preserve the viewport center, and pinch/Ctrl+wheel use the pointer as an anchor. The center line is a rotated great circle, so geographic meridians and parallels curve away from the focus. This mode recalculates geometry during panning as well as zooming.

ME and THEM labels sit in a separate strip beneath the map, aligned with the visible location markers. They stay clear of city names and follow horizontal panning and zoom. Labels for locations outside the current view are hidden; nearby labels separate so both remain readable.

Changing your timezone preserves the entered local dates and clock times. Changing the recipient's timezone preserves your availability. Overlapping or adjacent intervals merge for output. The text names the timezone once, shortens months and clock times, and ends with the year in brackets. Cross-midnight intervals include both dates. Timezone names appear at the first clause and whenever the timezone changes. A continuous interval whose endpoints use different offsets names the ending timezone immediately after “to”. Clock times stay free of repeated abbreviations. If the same long timezone name describes different offsets, its UTC offset is included to distinguish them. Dates spanning different years include those years beside the dates. Endpoints in skipped hours are rejected; endpoints in repeated hours require an explicit first/second occurrence choice. Times mean the complete available window, not permissible meeting start times.

The app uses the browser's built-in IANA timezone rules through `Intl.DateTimeFormat`. Keep your browser and operating system current for timezone law changes. Dates from 1900 through 2100 are supported; the UI is intended for present/future meeting scheduling.

The calendar always opens to the current week in your selected timezone. It does not restore a previously viewed week.

Source: `time.js` contains conversion, formatting, and away-hour calculations; `app.js` contains controls and city search; `settings.js` manages preferences and favorites; `map.js` draws the map and handles gestures; `projection.js` contains the earlier projection blend and inverse mapping; `focus-projection.js` and `focus-map.js` implement the viewport focus mode; `style.css` contains presentation. Geographic data licenses and attribution are in `DATA.md`.

Run regression checks with `node tests.cjs`, `node projection-tests.cjs`, and `node focus-tests.cjs`. Add `?profile=1` to the URL to reveal the optional zoom comparison; it keeps the map onscreen and reports update times and animation frame intervals for the original and the adaptive and viewport-focus modes. These timings include JavaScript and synchronous browser work, not an isolated GPU measurement.

## GitHub Pages updates

The live app is https://pmcarlton.github.io/meeting-windows/. GitHub Pages publishes `main` from the repository root. No build step is needed. Keep the HTML, JavaScript, CSS, bundled data, and vendor files together.

Make changes in this repository, run the regression checks above, then commit and push to `main`. GitHub Pages normally updates within a few minutes. Use a hard refresh if the browser still shows an older copy. `LICENSE` covers the application; `DATA.md` and the vendor license files document bundled third-party material.
